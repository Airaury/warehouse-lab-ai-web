# 仓序 LAB · 实验室物资风险与补货决策助手

## 本轮改进（2026-10-29）

- 登录后的每个业务页提供透明背景的原创 AI 虚拟形象“仓灵”：点击打开悬浮对话，支持快捷提问和连续追问。形象资源位于 `client/public/warehouse-guide.png`，同时用于右下角入口和对话面板头像。服务端每轮重新读取 MySQL 业务快照；前端只传最近 6 条对话作语义上下文，回答不直接写库。指定单一库区时服务端裁剪快照并拦截跨库区物资回答。页面卡片按滚动位置渐入。
- 总览直接运行 AI 风险分析，展示最近一次草案、工具核对次数和待确认建议；草案存于 MySQL，刷新后仍可查看。AI 仅使用只读工具，申请继续由人工确认并走审批。
- 数据分析按实验二 `index.html` 的 Chart.js 4.4.0 布局与动画呈现：全宽库区柱形图、全宽环形图，上下排列；点击库区后，柱形和环形图都按区内每种物资的当前库存数量展示，点击任一物资柱形、扇区或图例直接查看 14 天趋势。图表始终读取当前 MySQL 库存，跨单位“全部数量”只比较数值大小，不作为可加总库存；可切换到单一单位口径。
- 新物资可在“出入库 → 新物资建档入库”填写编码、分类、库区、单位、首次数量与安全阈值。服务端在一个事务内写入物资和第一条入库记录，重复编码返回明确提示。
- `npm run db:seed -w server` 幂等添加 20 种演示物资（总计 27 种），不覆盖已有库存；新环境的 `schema.sql` 同样包含这些物资。
- `npm run db:seed-trend -w server` 幂等写入可追溯的演示历史波动，适用于库存趋势展示；每种物资的历史净变化为 0，当前库存不变。界面会标明演示样本。
- 消息中心按审批、补货、库存、操作等类别叠卡展示，支持一键已读和 AI 分类简报；总览、库存和统计中的关键数字滚动更新。提供明暗主题、缓慢变化的背景、短转场和重点操作按钮反馈。
- 页面动效参考了 [Inspira UI](https://inspira-ui.com/) 的交互思路，具体实现为本项目代码。保留环境变量密钥配置，客户端不接收 AI API 密钥。

基于实验二仓库管理网页扩展的 Vue 3 + Express API + MySQL 作品原型，面向实验室与创客空间的物资管理者。DeepSeek 只由服务端调用，浏览器不会收到模型密钥。当前物资与历史记录为演示数据。

## 业务流程

库存预警 → AI 分析师调用只读工具核对库存、近期出入库、进行中补货 → 结构化草案与实际工具记录保存到 MySQL → 仓管员、主管或副主管逐项确认 → 主管或副主管审批 → 仓管员确认收货 → 库存、消息与统计更新。普通出入库直接登记；超过 50 的出库先经过审批。AI 本身没有写库工具。建议量由服务端按 `max(1, 2 × 安全阈值 − 当前库存)` 计算，提交时重新检查库存、重复申请和草案有效期（24 小时）。

## 岗位与页面

| 岗位              | 页面与权限                                                       |
| ----------------- | ---------------------------------------------------------------- |
| 主管 `MANAGER`    | 全部页面；审批出库和补货、创建或删除账号、重置他人密码、登记操作 |
| 副主管 `DEPUTY`   | 审批出库与补货、登记操作、申请与收货；不能管理账号               |
| 仓管员 `OPERATOR` | 总览、库存、出入库、补货、统计、AI、消息；可申请和收货           |
| 观察员 `VIEWER`   | 总览、库存、统计、AI、消息；可生成草案但不能提交申请             |

页面使用 Vue Router：`/`、`/inventory`、`/operations`、`/replenishments`、`/approvals`、`/analytics`、`/advisor`、`/notifications`、`/users`、`/security`、`/login`。前端路由和服务端权限同时限制操作。登录使用服务端随机会话、`HttpOnly`/`SameSite=Strict` Cookie；密码在 MySQL 中保存为 scrypt 加盐散列。用户可在“安全设置”凭旧密码改密；忘记密码时由主管在“账号管理”重置，重置会撤销旧会话。系统只有一名主管，不能新增主管或修改、删除主管账号；原有多名主管在升级时保留 `admin`（如存在）为主管，其余调整为副主管。主管删除其他账号采用逻辑删除：立即禁止登录、撤销会话，同时保留审批和操作记录。

## 本机运行

1. 安装 Node.js 20+ 和 MySQL 8。新安装时用 MySQL 管理员以 UTF-8 编码执行 [`server/schema.sql`](server/schema.sql)（MySQL CLI 请加 `--default-character-set=utf8mb4`）；重复执行不会重复插入演示物资。**已有数据库升级**需在私有环境变量中提供 `DB_ADMIN_USER`、`DB_ADMIN_PASSWORD` 后运行 `npm run db:migrate -w server`，脚本会为现有 `users` 表增添逻辑删除字段、副主管角色和唯一主管约束；仅重复执行 `schema.sql` 不会修改已有表结构。建表账号只用于迁移。
2. 复制 `server/.env.example` 为 `server/.env`。填写 `DB_USER`、`DB_PASSWORD`、`BOOTSTRAP_MANAGER_PASSWORD`（至少 12 位）、`AI_API_KEY`。如果沿用旧环境文件，首次创建主管时也可读取原有 `ADMIN_TOKEN` 作为初始密码；后续认证已不使用该口令。
3. MySQL 应用账号需要 `ai_warehouse` 上的 `SELECT, INSERT, UPDATE`，以及 `ai_warehouse.sessions` 上的 `DELETE`。`schema.sql` 末尾有授权示例。数据库管理员账号只用于建表和主管账号应急恢复，不用于日常 API 运行。
4. 在项目根目录运行 `npm install`、`npm run dev`，打开 `http://127.0.0.1:5173/`。首次启动会在用户表为空时创建账号 `admin`，密码为私有环境变量中的初始密码。主管登录后可在“账号管理”创建其他岗位账号。

```text
client (Vue 3 / Vue Router / Vite) → /api (Express) → MySQL 8
                                            └──────→ DeepSeek Chat Completions
```

服务端默认监听 `127.0.0.1:3001`，Vite 将 `/api` 代理到该端口。查看 `GET /api/health` 可确认数据库和 AI 配置状态。密钥只能写入忽略的 `server/.env` 或部署平台环境变量，绝不能写进 `VITE_` 前缀变量、浏览器源码、截图、公开仓库或演示资料。已在聊天或旧实验中暴露过的密钥应在服务商后台轮换。

### 董事长演示账号与场景

在私有 `server/.env` 中配置 12—128 位 `DEMO_CHAIRMAN_PASSWORD`，然后运行 `npm run db:seed-demo -w server`。脚本创建 `chairman_demo`（显示名“演示董事长”），系统角色为 `DEPUTY`：可演示审批和日常业务，不能管理账号，且不增加第二名主管。脚本还准备 3 条出库待审、3 条补货待审、带“演示场景”标记的出入库与分类消息，以及 2 种供 AI 分析的低库存物资。重复运行不会重复插入同一批场景；已有账号密码不会被脚本重置。演示密码只保存在私有环境变量，不放入公开仓库或答辩视频。

若唯一主管忘记密码，可由数据库管理员在**私有终端环境变量**中设置 `DB_ADMIN_USER`、`DB_ADMIN_PASSWORD`、`RECOVERY_USERNAME`、`RECOVERY_NEW_PASSWORD`（12—128 位），然后运行 `npm run account:recover -w server`。命令只恢复指定的现有主管账号并撤销其旧会话；不要把恢复密码写进命令行参数、README 或 Git 文件。

数据分析页使用与实验二 `index.html` 同版的 Chart.js 柱状图和环形图：上下全宽卡片、八色顺序、圆角柱、网格线、可点击的底部点状图例、悬浮提示与约 1 秒缓动；单物资 14 天库存趋势仍由本项目 SVG 展示。实验二 `landing.html` 是极光欢迎页，不含这两张图。图中数值始终来自当前 MySQL，因此物资数和柱高会与原实验的静态演示数据不同。原实验按分类汇总区内环形图，本项目按每种物资的实时库存数量绘制，以便点击后直接查看趋势。出入库页将登记与最近记录并列，按类型筛选，较早记录按需展开；补货页突出进行中申请，完成和拒绝记录默认折叠。消息中心支持一键已读，已读消息从未读列表淡出，仍可切换查看历史。品牌图标为项目自绘 SVG；登录页用可交互的四步流程展示业务闭环，AI 决策页使用深色光束与动画呈现分析入口。页面动效以短时反馈和环境氛围为主，不读取系统的“减少动态效果”偏好。

### 采购与领用界面取舍

当前定位是实验室内部物资决策系统，业务用户是领用人、仓管员、主管和潜在的采购员；不适合直接加入面向公众的购物车、支付和零售下单页。下一步优先补“领用申请”入口：实验人员选物资、数量、用途并提交，审批通过后仓管员拣货和出库，形成需求到库存变动的闭环。若要覆盖补货批准后的采购执行，再增设仅采购员可见的“采购订单”页，记录供应商、报价、交期、订单状态和到货对账，并与现有补货单和收货动作关联。供应商与价格尚无真实数据时，不应展示可提交的虚构采购订单。

## 验证

从根目录运行 `npm run build`；服务启动后在 `server` 目录运行 `node scripts/smoke.mjs`，将真实测试补货 1 单位并通过出库还原库存。运行 `node scripts/account-smoke.mjs` 可验证主管删号与重置、本人改密、会话撤销和消息一键已读；测试账号为临时账号，脚本结束后逻辑删除。设置私有环境变量 `RUN_AI=1` 可验证旧问答接口，`RUN_AI_PLAN=1` 可验证真实 DeepSeek 工具调用、草案、确认、审批、收货与库存还原。如现有主管密码与启动环境变量不同，可在本地设置 `SMOKE_SESSION=1` 使用五分钟测试会话；这会跳过登录密码检查，但仍检查会话与角色保护。业务测试保留申请、工具记录、消息和出入库审计记录。
