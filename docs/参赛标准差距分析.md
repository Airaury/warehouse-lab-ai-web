## 评分维度逐项核对

| 维度 / 权重 | 已有证据 | 核心差距 | 优先行动 |
| --- | --- | --- | --- |
| AI 技术深度 35% | DeepSeek 实际 function calling；3 个白名单只读工具；结构化草案、SKU 与阈值校验、服务端数量计算、工具调用审计、人工确认与审批 | 无 RAG/多模态/MCP，也没有离线测试集、模型准确率或人工反馈数据；旧问答仍是单次调用 | 先建立 20–30 个带期望结果的真实或脱敏场景测试，统计误报、漏报、重复建议和事实错误；再按真实需求决定是否引入知识检索 |
| 创新性 25% | 聚焦实验室/创客空间物资，AI 建议直接进入可追踪的审批闭环 | 场景仍由团队假设，暂无用户证实的独特痛点或与通用表格方案的对比 | 访谈实验室管理员，核实缺料、替代料、项目预约占用等高频场景并形成可验证差异 |
| 前端工程质量 10% | 路由拆页、组件与状态分离、构建通过；首页业务动效、结果过渡、加载态、减少动态效果支持 | 自动化前端测试、无障碍审计和性能数据不足 | 补关键流程浏览器自动化、键盘/读屏和 Lighthouse 记录 |
| 实用性 10% | MySQL 实时库存、AI 草案、审批、补货收货、消息和统计形成闭环 | 无真实供应商、采购、盘点、批次、条码和预约占用数据 | 由真实用户定义最小落地范围，优先接入项目预约与盘点样本 |
| 用户体验 10% | 总览风险可视化、AI 工具轨迹与证据卡、确认弹窗、SKU 图表和窄屏布局 | 未进行真实用户任务测试；模型文字判断仍需人工复核 | 让仓管员和主管完成 3 个定时任务，记录错误与完成时间并迭代 |
| 社会价值与商业潜力 10% | 减少实验中断与物资积压是明确待验证假设 | 没有 ROI、客户需求或收费模式验证 | 量化缺料影响、库存资金占用和部署成本，收集试用反馈 |

## `优秀设计.md` 的适用性

该文档是热门组件与设计资源的收藏，不是本项目的强制规范；其中星标、许可证与安装命令属于第三方信息，不能直接视作已核验事实。

| 文档设计元素 | 评估与应用 |
| --- | --- |
| ReUI 类后台表格、卡片、导航 | **适用**。实现了统一侧栏、指标卡、表格、审批卡与明确状态色；保留业务密度 |
| 图表、进度条与步骤条 | **适用**。实现单 SKU 14 天库存曲线、库区条形图、补货四步流程 |
| Cult UI 的 AI 分析面板模式 | **适用其交互思路**。实现独立 AI 决策页、示例问题、专业角色与结果区；未复制第三方源码 |
| Vue 生态 Inspira UI 的轻动效 | **已借鉴交互原则**。使用路由切换、库存曲线绘制、风险信号与结果进入动效，并支持减少动态效果；未增加 GSAP/Three.js 依赖 |
| 3D 场景、粒子背景、炫光营销 Hero | **不适用于高密度工作台**。总览首屏采用适度的风险决策视觉，核心表格和审批页保持任务密度 |

## 当前结论

项目已从仓库看板转为实验室物资风险决策原型，真实验证了 Vue + API + MySQL + DeepSeek 工具调用与审批闭环。**目前尚无可量化的 AI 质量评测和真实用户证据，也不是完整参赛提交包。** 下一轮优先建立场景评测集与用户测试，再制作视频、PDF 与线上演示。
